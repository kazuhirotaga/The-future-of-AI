# 執筆方針

## 文体

- 常体（だ・である）を基調とする。
- 一文は短く。読点で連ねない。息継ぎを多くする。
- 抽象語のあとには必ず具体を置く。逆はしない。
- 比喩は一章につき一つか二つ。多用すると論が濁る。
- 読者を「あなた」と呼ぶ。ただし説教しない。

## 構成の型

各章は次の順で進む。

1. **入口の情景**（200〜400字）
   抽象論から始めない。誰かの一日、ひとつの画面、ひとつの違和感から入る。
2. **問いの提示**
   その情景が何を意味するのか。読者と同じ疑問に立つ。
3. **本論**
   概念の導入 → 分解 → 反論の検討 → 再構成。
4. **反対側の視点**
   自説に都合の悪い事実を、必ず一節割いて扱う。
5. **この章の要点**（箇条書き3〜5項目）
6. **あなたの職場で考えること**（問い2〜3個）

## 事実の扱い

- **数字には必ず出典を添える。** 添えられない数字は書かない。
- 算術的に導ける数字（例：1年＝8,760時間）は出典不要だが、
  それが何を意味するかの解釈は「解釈である」と示す。
- 事例は次のいずれかに明示的に分類する。
  - **［報道・公開情報］** 出典を併記する
  - **［典型例］** 複数の実務から構成した合成事例であると明記する
  - **［思考実験］** 現実に起きた出来事ではないと明記する
- 「〜と言われている」「〜が指摘されている」という主語のない伝聞を使わない。

## 用語統一

| 使う語 | 使わない語 | 理由 |
|---|---|---|
| AIエージェント／エージェント | AI、人工知能（総称としてのみ可） | 対象を限定する |
| 影の労働 | シャドウワーク | 既存の社会学用語と混同されるため、初出で違いを説明する |
| 委任 | 丸投げ、自動化 | 責任が移らないことを含意させる |
| 稼働時間 | 労働時間 | 人間の労働時間と区別する |
| 停止条件 | 終了条件 | 技術文脈での慣用に合わせる |
| 検証 | チェック、確認 | 責任を伴う行為として区別する |
| 可逆性 | ロールバック可能性 | 非技術読者に開く |

## 陳腐化への備え

- 本文の骨格に、特定のモデル名・バージョン・性能値を置かない。
- 製品名は、その構造を説明するために不可欠な場合のみ、脚注扱いで出す。
- 「現在は」「本稿執筆時点では」という留保を、時制が問題になる箇所に必ず入れる。
- 技術の詳細ではなく、**その技術が何を可能にしたか**を書く。
  実装は変わるが、可能になったことの意味は残る。

## やらないこと

- 恐怖で動機づけない。「乗り遅れる」という語彙を使わない。
- 万能感を煽らない。できないことは、できないと書く。
- 読者の職業を否定しない。「その仕事はなくなる」と断定しない。
  代わりに「何が変わり、何が残るか」を分解する。
- 結論を先送りしない。各章は必ず自分の立場を述べて終わる。
